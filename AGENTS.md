# AGENTS.md

## Learned User Preferences

- Use Bun exclusively — `bun`, `bunx`, never `npm`, `npx`, `yarn`, or `pnpm`
- Follow Conventional Commits — atomic commits, imperative mood, no AI/tool/agent references or trailers (`Made-with: Cursor`, `Co-authored-by: AI`); always show a commit review report and wait for explicit approval before committing
- Apply DRY, KISS, and SOLID principles — prefer simpler state over nullable + guards; avoid overengineering (prefer simple fixed config over port-check scripts when complexity adds minimal value); extract complex inline casts or nested ternaries into named helper functions; disable overzealous lint rules at config level rather than scattering disable comments; prefer discoverable upper_snake env flags for operational toggles (limits, logging, throttle) instead of hiding behavior in code; remove temporary compatibility shims and duplicated folder structures once migrations are complete
- Review from a senior staff engineer / head-of-engineering perspective when asked, including OWASP-oriented gaps when changes touch transport, persistence, or abuse surfaces; for editor plugin code, review as ProseMirror/Tiptap core author checking for performance issues and memory leaks; when review delegation is requested, use the `code-reviewer` subagent
- Prefer `lucide-react` icons via `lib/icons.tsx` barrel file; brand SVGs (Discord, GitHub) also live there — avoid one-off icon wrapper components elsewhere
- Use named exports only (no `export default` except where required by framework); title-case acronyms in PascalCase names — `TocSidebar` not `TOCSidebar`
- Avoid hydration mismatches — never use `useState(() => loadFromLocalStorage())`; use `useEffect` with a "ready" state flag; never nest `<button>` inside `<button>`
- Prefer margin-positioned layout (e.g. TOC in left margin) so main content stays centered; TOC item click: cursor at end of heading node, scroll heading to top of viewport (`block: "start"`, not center), defer scroll via `requestAnimationFrame` after selection/focus settle
- Use shadcn/ui components from `components/ui/` for new UI — design tokens are shadcn CSS variables; `--tt-*` tokens remain only for editor node SCSS
- Keep `.cursor/skills/` and `.cursor/rules/` tracked in git — never ignore them
- Always verify changes by running them — open the app and screenshot for UI; run tests end-to-end for test code; fix issues before considering work done
- When writing specifications or design documents, keep them self-contained; update related docs after feature implementation to keep teams synchronized
- Record every merged change in `CHANGELOG.md` (Keep a Changelog, grouped by merged PR, newest first, with an operator "Deploy" note when a release needs one); add the entry under Unreleased in the same PR
- Prefer working in parallel on independent tracks (background agents in isolated worktrees with disjoint file ownership), then integrate, resolve overlaps and re-verify everything in one place
- Never test against the live site (tiny.docs.plus); reproduce on localhost with production builds when behaviour depends on them

## Learned Workspace Facts

- TinyDocy is a lightweight collaborative editor testbed for docs.plus, positioned as an online-capable demo where abuse and OWASP-minded guardrails matter; stack is Next.js 16 App Router + Tiptap 3 + Yjs + Hocuspocus + SQLite, with Bun runtime
- Persistence is Hocuspocus 4 WebSocket + SQLite via custom `bun run hocus` (`scripts/hocus-server.ts`: `Bun.serve` + `Hocuspocus.handleConnection`, `bun:sqlite`) with fetch/store persistence in `lib/hocus-persistence.ts` on the `extension-sqlite`-compatible `documents` table, custom WS guardrails in `lib/security/*`, and optional official `extension-logger` / `extension-throttle` / `extension-redis` toggled by `HOCUS_*` env; local dev starts both services with `make dev` (`make -j2`)
- Runtime: everything runs on Bun ≥ 1.4.4 (`.tool-versions`) — `bunfig.toml` `[run] bun = true` makes `bun <bin>` and `bun run` start package bins (Next.js, ESLint, Playwright, commitlint) on the Bun runtime, but plain `bunx` ignores it and uses Node when installed, so call local bins as `bun <bin>` (e.g. `bun playwright test`) and remote ones as `bunx --bun`; CI puts a failing `node` stub on PATH after install so nothing falls back to Node; SQLite is `bun:sqlite` everywhere (`openSqlite()` in `lib/sqlite-open.ts`, used by the Next.js API, Hocus and scripts; `.get()` returns `null` for no row); the app `tsconfig.json` uses Bun types and `bun run typecheck` checks it plus `tsconfig.sw.json`
- Root `README.md` is the only README (reader-first: features, quick start, architecture, config tables, deploy requirements, docs index); release history lives in `CHANGELOG.md`; tests docs live in `tests/TESTING.md`; operations runbooks live in `docs/operations/` (abuse guardrails, analytics, service worker); avoid full PM2/Traefik step-by-step guides
- Code quality/tooling: Biome for formatting/linting, ESLint scoped to Next.js rules, strict TypeScript; Husky runs lint-staged pre-commit and commitlint on commit-msg
- Naming and exports: kebab-case files, PascalCase components with title-case acronyms, camelCase hooks/utils, named exports by default
- Top-level editor children get `position: relative` (`paragraph-node.scss`) except the HyperMultimedia resize gripper, which positions itself absolutely from its offsetParent
- shadcn/ui components in `components/ui/` are the default for new UI; old `tiptap-ui-primitive` is fully replaced
- Utilities are domain-split in `lib/`: `utils.ts`, `shortcuts.ts`, `editor-utils.ts`, `icons.tsx`, `user-identity.ts`, `yjs-mark-migration.ts`, `site-config.ts` (single source of public copy for metadata, intro, JSON-LD, /about, llms.txt), `analytics*.ts` (opt-in GA4), `collab-session.ts`, `offline/` and `pwa/`
- Collaboration sessions: `lib/collab-session.ts` multiplexes every document (tab list and editors) on one shared `HocuspocusProviderWebsocket` with a reference-counted cache and deferred release (attach/detach of the same name in one tick races the server Close); sessions with unsynced edits stay alive; size refusals (`document_too_large`) and deleted documents (`document_deleted`) detach the provider and make the editor read-only instead of reconnecting (reconnect loops get IPs banned by Throttle)
- Offline editing is on by default: `lib/offline/` stores compacted Yjs state per document in IndexedDB (epoch + server-host scoped keys, 14-day expiry, 30-doc cap, never evicting open or unsynced docs), applied before the provider attaches (never after sync, which would re-upload the whole copy); seeding, tab-list bootstrap and the copy sweep wait for a real server sync; tab titles change only on local edits (`isChangeOrigin`); offline edits pause at 512 KiB; `NEXT_PUBLIC_OFFLINE_CACHE=0` disables and wipes copies
- "Continue where you left off" (M15): `lib/continue-position.ts` stores the section heading's `data-toc-id` per document in `tinydocy-continue` (local only, never Yjs; 30 docs, 14 days; off under `NEXT_PUBLIC_REMEMBER_CHOICES=0`), recorded on editor blur, hidden, pagehide and tab switch only after the writer's own selection or edit; the chip (`components/document-editor/continue-chip.tsx`) is one lazy chunk that imports no editor-chunk module (a shared module splits the editor group, about +1.6 KB): the eager `continue-chip-loader.tsx` passes the editor helpers it needs as a prop; Go and the outline share `goToHeading` (`lib/heading-navigation.ts`)
- PWA: manifest `id` is frozen at `/`; Next 16 native Turbopack service worker (`lib/pwa/service-worker.ts`, served at `/_next/static/service-worker/sw.js`, production only) is network-first for HTML and cache-first for `/_next/static`, never handles `/api`, RSC, cross-origin or WebSockets; kill switch via `NEXT_PUBLIC_SERVICE_WORKER=0` plus `KILL_SWITCH`; `bun run typecheck` covers two projects (app, `tsconfig.sw.json`)
- Loading performance: server-rendered app-shell skeleton (`components/app-skeleton`) with the SEO intro in its page card; the editor is a lazy chunk preloaded during tab sync; `extensions/render-once/` renders a collaborative doc once on mount; `extensions/table-of-contents/fast-table-of-contents.ts` replaces the stock TOC's per-keystroke `offsetTop` reads; off-screen top-level blocks use `content-visibility: auto` except the caret's block (`CaretBlockVisible` adds `.is-caret-block`; Chromium misplaces the caret when typing into a skipped block, e.g. right after Enter)
- Colour hover preview (`extensions/action-preview/`): one eager plugin whose only state is a `DecorationSet`, set by the meta-only `setActionPreview` command (`addToHistory: false`, no steps or selection, so no Yjs, undo or toolbar notify) cleared by a local doc or selection change and redrawn on the moved selection after a collaborator's change (never mapped); the swatch side (`components/smart-toolbar/color/swatch-preview.ts`, lazy colour chunk) calls only the command and imports nothing new from the editor chunk; never `registerPlugin` from a lazy chunk (it re-creates every plugin view); `NEXT_PUBLIC_ACTION_PREVIEW=0` disables it
- Typing performance: never subscribe the editor shell to editor state or rebuild the extensions array per render (Tiptap calls `setOptions`); toolbar controls re-render through `useTiptapEditor`'s shared store (`TOOLBAR_SETTLE_MS` 150 ms after document changes, immediate for selection/marks/focus, capped at `TOOLBAR_MAX_WAIT_MS` 1 s during continuous remote changes, never during local typing); outline items live in a separate store, rebuild at most every 250 ms and can be stale, so look headings up by id (`findTocAnchor`); code highlighting is incremental (`incremental-lowlight.ts`); the y-tiptap sync view skips updates without a doc change
- Security model for the public sandbox: tombstones (`document_tombstones`, `TOMBSTONE_RETENTION_DAYS` 90, also written by the retention purge) block deleted names at connect and load; system docs are only `playground` and `global-tabs` (per-test `global-tabs-*` need `HOCUS_ALLOW_ISOLATED_TABS_DOCS=1`, refused in production); size is enforced on incoming updates (`lib/security/hocus-document-guard.ts`, delete-only updates allowed at the cap); sockets are gated at upgrade (per IP, total, rate, `HOCUS_ALLOWED_ORIGINS`); code-block languages are validated (`SafeCodeBlock`); Mermaid SVG is sanitized with DOMPurify; media embed hosts are allowlisted by exact host in `lib/security/content-security-policy.ts`
- Production deploy (owner runs it): `/opt/projects/editor.docs.plus`, PM2 via `bunx pm2@6.0.14` with `ecosystem.config.cjs` (Next 3847, Hocus 3848, Redis 6380, `MAX_DOC_SIZE_BYTES=2097152`, `HOCUS_ALLOWED_ORIGINS=https://tiny.docs.plus`), Traefik in front (`tiny.docs.plus`, `ws.tiny.docs.plus`); build-time `NEXT_PUBLIC_*` values live in `.env.production`; restart with `--update-env` after env changes
- Tabs are synced through Y.Doc `global-tabs` (`useSyncedTabs`) with Playground fixed at index 0; `activeTabId` is local per user; close operations call `DELETE /api/documents/[id]`, which is HTTP rate-limited separately from WS throttles on Hocuspocus; the canonical editor implementation lives in `components/document-editor/` (legacy `components/tiptap-templates/simple` has been removed)
- Simplified toolbar (contract A15) is CSS only: `data-toolbar-density="simple"` on the row applies the ladder's T2–T4 `collapse-tier` mixin at every width (the ladder still collapses further below T4/T5); the setting is the `toolbarDensity` slot in `tinydocy-ui` (survives Forget), read by `useToolbarDensity` (`useSyncExternalStore`, no ready flag: the editor is `ssr: false` and a ready effect would flash the full row); `view.simpleToolbar` writes it, ⋯ shows it as a checkbox from the lazy menu chunk
- TOC supports dnd-kit drag-and-drop and section move semantics via `moveSection()`; heading-level and fold behavior are plugin-driven and optimized for large docs; collaboration carets use `@tiptap/extension-collaboration-caret` with `HocuspocusProvider`; user identity is persisted in localStorage (`tinydocy-user`)
- Heading stack extensions (fold, filter, drag, scale) should stay cleanly bounded so other Tiptap apps can adopt them without pulling in the full `components/document-editor` shell
- Document schema enforces title-first (`heading block*`), heading levels 1-6, and title-scoped paste handling; empty docs are seeded when the Yjs fragment is empty after a server sync
- Editor uses the `@docs.plus/extension-*` packages (Hyperlink, InlineCode, Indent, Placeholder, Mermaid, HyperMultimediaKit) in place of StarterKit `link`/`code`, `@tiptap/extensions` Placeholder and `@tiptap/extension-image`; mark names are `hyperlink` and `inlineCode` (legacy `link`/`code` in stored Yjs docs are renamed server-side in Hocuspocus `afterLoadDocument`); the extensions render their own popovers/toolbars, so `tiptap-ui` only adds toolbar triggers; `.github/workflows/docs-plus-extensions.yml` refreshes them daily (04:17 UTC) via PR
- CI: `.github/workflows/ci.yml` runs on PRs and pushes to `main` (checks job: `bun audit --audit-level=high`, Biome, ESLint, typecheck, unit tests without `tests/unit/stress`, build; e2e job: `make dev`, warm-up, `CI= bun playwright test --project=chromium --project=perf --retries=1`, where `perf` runs `performance.spec.ts` on one worker after `chromium`); the stress probe is a non-blocking timing benchmark; `tests/unit/ci/workflow-permissions.test.ts` requires explicit read-only job permissions, `persist-credentials: false` and SHA-pinned actions in every workflow; `.github/workflows/nightly.yml` (03:41 and 08:00 UTC and on demand) runs the `pwa` project on a production build, yjs-soak, quick soaks and the load harness; releases: push a `vX.Y.Z` tag on `main` and `.github/workflows/release.yml` publishes the GitHub release (generated PR list + CHANGELOG link); the docs.plus update workflow starts CI on its branch with `gh workflow run` (bot-made PRs start no workflows, and CI is a required check)
- Testing stack is `bun test` (happy-dom preload; all files share one process, so `mock.module` spreads the real module and is followed by `await import()`, and import-time env goes through `importFresh()` + `resetModules()` in `afterEach`) + Playwright (+ Yjs load/soak harness); `EditorPage.waitForSync()` waits for `data-server-synced` (editable earlier from the device copy), and tests type at full speed: misplaced text means an app bug, not a missing wait; use `bun run test` (it skips the stress probe; `bun run test:stress` runs it), run Playwright with `CI=` against existing dev servers, and use `window.__HOCUS_URL`/`window.__HOCUS_TOKEN`/`window.__GLOBAL_TABS_DOC` hooks for test isolation; subprocesses that spawn `bun run hocus` for reconnect-heavy flows should set `HOCUS_THROTTLE=0` so official throttle does not false-positive ban clients; e2e hocus also needs `HOCUS_ALLOW_ISOLATED_TABS_DOCS=1` and raised socket limits (see `playwright.config.ts`), and `next dev` and hocus must share one `DB_PATH` (the DELETE route and Hocuspocus read the same tombstones); e2e needs `next dev` because helpers use `window.__tiptap_editor`; the `pwa` Playwright project runs only against a production build (`PWA_BASE_URL`); all other projects block service workers
